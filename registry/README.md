# Реестр: участники, команды, назначения

> **Статус: проект структуры, согласуется.** Предложен 2026-09-20 к G1 (24.09.2026).
> Пока не согласован — файлы заполняются только примерами из этого README, реальные записи не
> вносятся.
>
> Реестр — рабочий контур мастерской ([`../program/governance.md`](../program/governance.md) § 1).
> Академический контур (зачёт, кредиты, расписание, посещаемость) живёт в системах вуза; сюда
> **не переносится**.

## Зачем

Один источник правды о том, **кто в каком воркстриме, в какой команде и в какой роли** в каждом
семестре. Все остальные списки (таблица «Команда» в карточке воркстрима,
[доска](../workstreams/board.md), выписка вклада для зачёта) — представления из реестра, а не
самостоятельные списки.

## Модель

Главная единица учёта — не учебная группа, а связка:

```
участник → семестр → воркстрим → команда → роль
```

```
  participants            semesters            workstreams
  (человек,               (ход курса,          (тема, живёт
   живёт постоянно)        1 семестр)           годами; id = имя
        │                      │                папки в workstreams/)
        │                      │                      │
        └──────────┬───────────┴──────────┬───────────┘
                   │                      │
                   │                   teams
                   │                   (команда воркстрима
                   │                    на один семестр)
                   │                      │
                   └──────► memberships ◄─┘
                            (назначение роли: от даты до даты)
```

**Команда — не воркстрим.** Команда собирается на один ход и после семестра исчезает; воркстрим
остаётся и принимает следующую команду ([governance § 1](../program/governance.md)). Поэтому
`teams` и `workstreams` — разные сущности, а не одна.

**История не теряется.** Человек осенью 2026 — аналитик поля в команде воркстрима «Развитие
территорий», весной 2027 — шерпа того же воркстрима. Это две строки в `memberships` с разными
`semester_id` и `role`, а не правка одной строки. Лестница «участник → капитан → шерпа → владелец»
([governance § 9](../program/governance.md)) читается как история строк по одному `person_id`.

### Пять сущностей

| Сущность | Файл | Живёт | Пример id |
|---|---|---|---|
| Участник | [`participants.csv`](participants.csv) | Постоянно | `p001` |
| Семестр (ход курса) | [`semesters.csv`](semesters.csv) | 1 семестр | `2026-fall` |
| Воркстрим | папки в [`../workstreams/`](../workstreams/) | Несколько семестров / лет | `territories` |
| Команда | [`teams.csv`](teams.csv) | 1 семестр | `territories-2026-fall-01` |
| Назначение роли | [`memberships.csv`](memberships.csv) | От даты до даты | `m0001` |

Отдельного файла воркстримов нет намеренно: источник правды о воркстриме — его карточка
`workstreams/<id>/README.md`, а `workstream_id` — это имя папки. Второй список воркстримов
разошёлся бы с картой.

## Файлы и колонки

Формат — CSV, первая строка — названия столбцов ([`../rules/data-collection.md`](../rules/data-collection.md)).
Кодировка UTF-8, разделитель — запятая. Значения с запятой внутри — в двойных кавычках.

> **Excel** может показать кириллицу кракозябрами при двойном клике. Открывайте через
> «Данные → Получить данные → Из текстового/CSV-файла», кодировка «UTF-8».

### `participants.csv` — люди

| Колонка | Что | Значения |
|---|---|---|
| `person_id` | Устойчивый номер, **никогда не меняется и не переиспользуется** | `p001`, `p002`, … |
| `github` | Ник в GitHub — связь с цифровым следом | `ivanov` |
| `display_name` | Как человека называть в репозитории | Пока репозиторий публичный — **ник**; после закрытия — ФИО |
| `org` | Вуз или организация | `СПбГУ`, `СПбГМТУ`, `Ингосстрах` |
| `unit` | Подразделение, курс, группа | `Экономика, 3 к.`, `ИСвЭ, магистратура` |
| `type` | Кто человек институционально | см. словарь ниже |
| `status` | Состояние | `active`, `paused`, `alumni` |
| `first_semester` | Первый семестр в мастерской | `2026-fall` |
| `note` | Свободная пометка | |

**Контакты и ФИО здесь не хранятся, пока репозиторий публичный.** Они живут в закрытой таблице —
см. [«Что сюда не пишется»](#что-сюда-не-пишется).

### `semesters.csv` — ходы курса

| Колонка | Что |
|---|---|
| `semester_id` | `2026-fall`, `2027-spring` (как в именовании кейсов, [`../CONTRIBUTING.md`](../CONTRIBUTING.md)) |
| `title` | «Осень 2026» |
| `date_start`, `date_end` | `ГГГГ-ММ-ДД` |
| `note` | Ссылка на календарь, особенности хода |

### `teams.csv` — команды

| Колонка | Что | Значения |
|---|---|---|
| `team_id` | `<workstream_id>-<semester_id>-<NN>` | `territories-2026-fall-01` |
| `workstream_id` | Имя папки в `workstreams/` | `territories` |
| `semester_id` | | `2026-fall` |
| `title` | Человеческое название команды, если есть | |
| `captain_person_id` | Капитан | `p001` |
| `sherpa_person_id` | Шерпа команды | `p007` |
| `gate` | Текущий гейт | `G0`…`G5` |
| `status` | | `forming`, `active`, `blocked`, `closed` |
| `origin` | Откуда команда | `spbu`, `external-guest`, `mirror` |
| `note` | | |

`origin` различает свою команду, гостевую и зеркальную ([governance § 10](../program/governance.md),
модели A–D).

### `memberships.csv` — назначения ролей (ядро реестра)

Одна строка = один человек в одной роли в одном ходе. Смена роли — **новая строка**, а не правка
старой.

| Колонка | Что | Значения |
|---|---|---|
| `membership_id` | | `m0001` |
| `person_id` | Кто | `p001` |
| `semester_id` | Когда | `2026-fall` |
| `workstream_id` | В какой теме; пусто для ролей уровня программы | `territories` |
| `team_id` | В какой команде; **пусто для ролей уровня воркстрима и программы** | `territories-2026-fall-01` |
| `role` | Что делает | см. словарь |
| `profile` | Уточнение внутри роли | `gis`, `prototyping`, … |
| `date_from`, `date_to` | Границы назначения; `date_to` пусто, пока действует | `2026-09-24` |
| `exit_type` | Как вышел | `g5`, `planned`, `silent` |
| `sponsor_person_id` | Кто ведёт: шерпа, для внешних — обязателен | `p007` |
| `gate_in` | На каком гейте вошёл | `G1`, `G2` |
| `note` | | |

**Три уровня назначений** различаются тем, какие поля заполнены:

| Уровень | `workstream_id` | `team_id` | Пример роли |
|---|---|---|---|
| Программа | пусто | пусто | `master`, `faculty-coordinator` |
| Воркстрим | заполнен | пусто | `workstream-owner`, `sherpa`, `stake-holder` |
| Команда | заполнен | заполнен | `captain`, `field-analyst` |

Это важно: шерпа ведёт команду, но не входит в неё; владелец воркстрима держит тему поверх
команд. Без пустого `team_id` их пришлось бы записывать как участников команды, чего в модели нет.

## Словари значений

Значения — латиницей, как имена папок ([`../CONTRIBUTING.md`](../CONTRIBUTING.md)): так они не
расходятся в написании. Русские названия — в таблицах ниже.

### `type` — кто человек

| Значение | Кто |
|---|---|
| `student-spbu` | Студент СПбГУ |
| `student-external` | Студент другого вуза |
| `teacher` | Преподаватель |
| `partner` | Представитель партнёра |
| `staff` | Сотрудник факультета |

### `role` — что человек делает

Роли команды ([`../roles/README.md`](../roles/README.md); набор уточняется в
[issue #2](https://github.com/SPBUEcon/econ-library/issues/2)):

| Значение | Роль | Профили (`profile`) |
|---|---|---|
| `captain` | Капитан | — |
| `model-architect` | Архитектор модели | `economic`, `organizational`, `financial` |
| `field-analyst` | Аналитик поля | `data`, `interviews`, `field-research` |
| `tech-integrator` | Интегратор технологий | `gis`, `prototyping`, `ai-tools` |
| `partner-liaison` | Связной с партнёром | `communications` |

Роли воркстрима и программы (устойчивые, не пересматриваются):

| Значение | Роль |
|---|---|
| `master` | Мастер |
| `faculty-coordinator` | Координатор факультета |
| `workstream-owner` | Владелец воркстрима |
| `stake-holder` | Носитель ставки (партнёр) |
| `sherpa` | Шерпа |

### `exit_type` — как человек вышел

| Значение | Что значит |
|---|---|
| `planned` | Ход завершён, вышел штатно |
| `g5` | Вышел досрочно, но через мини-G5 — наследство передано |
| `silent` | Тихое исчезновение. Единственное, что учитывается при входе в следующие семестры ([governance § 10](../program/governance.md)) |

## Правила записи

| Событие | Кто вносит | Что вносит | Когда |
|---|---|---|---|
| Новый человек | Шерпа | Строка в `participants.csv`; `person_id` = следующий свободный | В день подтверждения роли |
| Команда собрана (G1) | Шерпа | Строка в `teams.csv` + строки в `memberships.csv` на каждого | В день гейта |
| Смена роли | Капитан → шерпа | Закрыть старую строку (`date_to`), завести новую | В течение недели |
| Выход участника | Шерпа | `date_to` + `exit_type` | В течение недели |
| Вход внешнего | Шерпа-спонсор | `participants.csv` + `memberships.csv` с обязательным `sponsor_person_id` и `gate_in` | После мини-G1 |
| Закрытие хода (G5) | Шерпа | Проставить `date_to` и `exit_type` всем; `status` команды = `closed` | При закрытии хода |
| Сверка | Мастер | Реестр ↔ доска ↔ карточки ↔ история репозитория | На каждом гейте |

Порядок изменений — как для всего репозитория: ветка, Pull request, ревью шерпы
([`../rules/team-work.md`](../rules/team-work.md)). Правка реестра — такой же цифровой след, как
и всё остальное: видно, кто и когда внёс запись.

### Правила целостности

- `person_id` уникален и постоянен; человек не заводится дважды при смене вуза или роли.
- `team_id` уникален; в нём `workstream_id` и `semester_id` совпадают с колонками.
- `workstream_id` — существующая папка в [`../workstreams/`](../workstreams/).
- У команды ровно один капитан в один момент времени.
- У внешнего участника (`type = student-external`) `sponsor_person_id` обязателен.
- Строки **не удаляются**: закрытое назначение остаётся с `date_to`. Реестр — история, а не срез.

## Представления

Из реестра собираются, а не ведутся отдельно:

| Представление | Где | Как получается |
|---|---|---|
| Состав команды | Таблица «Команда» в карточке воркстрима | Фильтр `memberships` по `workstream_id` + текущему `semester_id`, где `date_to` пусто |
| Доска «воркстрим × гейт» | [`../workstreams/board.md`](../workstreams/board.md) | `teams` по текущему семестру |
| Выписка вклада (для зачёта) | По запросу | Все `memberships` одного `person_id` + артефакты гейтов и коммиты |
| Траектория человека | По запросу | `memberships` одного `person_id` по семестрам |

Дублирование в карточках допустимо для читаемости, но при расхождении **прав реестр**.

## Что сюда не пишется

| Не пишется | Где живёт | Почему |
|---|---|---|
| ФИО (пока репозиторий публичный), Telegram, email, телефон | Закрытая таблица у мастера, координатора и шерп; ключ — `person_id` | Репозиторий сейчас открыт; после закрытия его увидят все члены команд, а контакты всех участников нужны не каждому |
| Оценки, зачёты, посещаемость | Ведомость вуза | Академический контур |
| Персональные данные третьих лиц | Никуда | [`../rules/data-collection.md`](../rules/data-collection.md) |

Шаблон закрытой таблицы — [`_contacts-template.csv`](_contacts-template.csv) (только заголовки).
Заполненный файл в репозиторий не попадает: закрыт в [`../.gitignore`](../.gitignore).

`memberships.csv`

```csv
membership_id,person_id,semester_id,workstream_id,team_id,role,profile,date_from,date_to,exit_type,sponsor_person_id,gate_in,note
m0001,p001,2026-fall,territories,territories-2026-fall-01,captain,,2026-09-24,,,p007,G1,
```

## Открытые вопросы к согласованию

1. **Где закрытая таблица** с ФИО и контактами: таблица факультета или отдельный закрытый
   репозиторий у мастера и шерп.
2. **Формат `person_id`:** сквозной `p001` или привязанный к семестру входа.
3. **Нужна ли проверка целостности** скриптом (битые id, дубли, команда без капитана) — можно
   добавить как автоматическую проверку на Pull request.
4. **Что делать при смене GitHub-ника** — колонка `github` меняется, `person_id` остаётся;
   нужна ли история ников.
5. **Роли команды** зависят от решения по [issue #2](https://github.com/SPBUEcon/econ-library/issues/2):
   если набор изменится, словарь `role` меняется вместе с ним.
