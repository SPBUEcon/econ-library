# Стенд: ИИ-слой геоплатформы

> **Формула стенда:** клиентские сервисы геоинформационной платформы, в которых ответ, консультация и
> геоотчёт с ИИ имеют известную стоимость, проверяются машинно и не выпускают чувствительные данные
> за пределы контура.

> **Статус: в согласовании** (заведён 2026-10-09). Рамка и задание согласуются с Геоинтеллектом
> (ООО «ЦПИ»); до подтверждения партнёром стенд не выходит на витрину, а задания не выдаются.
> Основа — проект задания на курсовую работу от ЦПИ (v2, октябрь 2026) и внутренняя проработка ЦПИ
> по ИИ-слою платформы. **Оригиналы в публичный репозиторий не кладутся:** здесь только то, что нужно
> для заданий, в обобщённом виде, без внутренних планов и коммерческих сведений партнёра. Модель
> стендов — [`../README.md`](../README.md), архитектура — [`../../program/architecture.md`](../../program/architecture.md).

## Почему стенд, а не воркстрим

- Курсовая — задача горизонта Н2 (один семестр); воркстрим — задача Н3. Тема переживает несколько
  ходов (сценарии 1 → 2 → 3 → перспектива), поэтому ей нужен стенд, на котором сменяются задания.
- У сквозного воркстрима [«ИИ, цифровые двойники и симуляции»](../../workstreams/ai-environment/README.md)
  не было ни стенда, ни барьера от партнёра; этот стенд даёт ему первый.
- Ядро общее со стендом [ГИС · спорт СПб](../geo-sport-spb/README.md): доступность, изохроны,
  обеспеченность — те же операции, что в геоотчётах (сценарий 3). Переопыление — в обе стороны.
- Проект задания ссылается на воркстрим «Развитие территорий», которого нет в
  [карте](../../workstreams/README.md), — [открытый вопрос](../../program/open-questions.md) (№ 13).

## Замысел (инверт)

Партнёр знает, **сколько стоят** ответ, консультация и геоотчёт, подготовленные с ИИ, и умеет снижать
эту стоимость без потери качества: дешёвые задачи решаются без модели или малой моделью, сложные
поднимаются на ярус выше только после непройденной машинной проверки, а решение о том, можно ли
выпускать данные наружу, принимается **до выбора модели**. Эталонный набор гео-задач, библиотека
методик и шаблоны отчётов накапливаются от хода к ходу и переходят к следующим командам.

Сценарии образуют лестницу: каждый следующий опирается на средства, созданные для предыдущего.

| Сценарий | Что делает ИИ | Ключевой актив | Главный риск |
|---|---|---|---|
| 1. Справочный чат | Отвечает по инструкциям и тарифам | База знаний | Выдуманные цены и обещания |
| 2. Чат-консультант | Объясняет, как решить задачу клиента средствами сервиса | Библиотека методик | Неверные выводы для бизнеса клиента |
| 3. Геоотчёт по запросу | Превращает свободный запрос в расчёт и отчёт | Шаблоны отчётов, API сервисов | Числа в тексте расходятся с расчётом |
| Перспектива | Проектирование территории | — | За рамками стенда этого хода |

## Слой Ф — фундамент ИС

Архитектура маршрутизатора (одна для всех сценариев; меняется наполнение и доступные ярусы):

```
обращение --> кэш похожих вопросов --(нет)--> классификатор намерения и сложности
          --> политики: 1) можно ли выпускать данные  2) сложность  3) бюджет и режим
          --> ярус: без модели · малая · средняя · тяжёлая --> исполнение --> машинная проверка
          --(не пройдена)--> ярус выше с текстом ошибки --(невозможно)--> сотрудник партнёра
          --> журнал: модель, токены, стоимость, время, результат проверки
```

| Компонент | Что это | Где | Статус |
|---|---|---|---|
| База знаний и поиск | Ответ только по найденным фрагментам, со ссылкой на источник | прототип команды | цель |
| Кэш похожих вопросов | Проверенный ответ без обращения к модели | прототип команды | цель |
| Классификатор | Тип обращения и наличие методики или шаблона | прототип команды | цель |
| Политики и каскад эскалации | Порядок решений, критерии эскалации и передачи человеку | архитектурный документ | цель |
| Журнал стоимости и качества | Каждый шаг: модель, объём, стоимость, время, проверка | репозиторий команды | цель |

**Ярусы моделей** (базовая классификация, уточняется по результатам):

| Ярус | Типовые задачи | Средство |
|---|---|---|
| Без модели | Ответ из кэша, поиск, расчёт на платформе, проверка чисел | Поисковый индекс, PostGIS, API сервисов |
| Малые | Намерение, разбор запроса в параметры, выбор методики или шаблона | Локальные модели небольшого размера |
| Средние | Ответ по фрагментам, ведение по методике, текст выводов | Крупные локальные или облачные модели |
| Тяжёлые | Нестандартные запросы вне шаблонов | Наиболее сильные доступные модели |

## Вовлечение

Механики — [`../engagement.md`](../engagement.md).

**Студенты на занятии (Н0):** разметка синтетических обращений; спор «какой ярус нужен этой задаче».

| Партнёр | Ступень сейчас → цель хода | Данные: уровень сейчас → цель (D0–D6) | Коммуникация |
|---|---|---|---|
| Геоинтеллект (ЦПИ) | шерпа / эксперт → носитель задачи стенда (*в согласовании*) | *заполнить* → обезличенные обращения по соглашению о конфиденциальности | дайджест, контрольные точки 1, 2, 4 |

**Возврат партнёру:** эталонный набор, прототип маршрутизатора, оценки стоимости ответа,
консультации и геоотчёта в сравнении с работой сотрудников, записка с рекомендациями.

**Данные партнёра:** только по соглашению о конфиденциальности; в открытой части репозитория — только
открытые или синтетические данные; ключи доступа к моделям в репозиторий не кладутся.

## Тезисы по запросу

Нужны: стоимость ответа ИИ и каскады моделей (FrugalGPT, RouteLLM); поиск с генерацией (RAG);
«модель строит цепочку операций, считают детерминированные движки»; данные решаются до выбора модели.
