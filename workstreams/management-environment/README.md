# Воркстрим: Среда управления мастерской

> **Инфраструктурный воркстрим.** Его предмет — развитие самой среды, в которой живёт мастерская:
> этот репозиторий (единый репозиторий воркстримов), стенды, шаблоны, автоматизация, навигатор
> и витрина. Развитие среды ведётся как воркстрим — с наследованием и цифровым следом.
>

## Суперзадача

Развивать единую **вузонезависимую** среду управления мастерской, чтобы наследование, цифровой
след и вовлечение работали без ручной рутины: репозиторий воркстримов и стендов, шаблоны
(карточка воркстрима, стенд, дайджест, протокол поля, соглашение о входе), автоматизация
(дайджесты партнёрам из журналов стендов, формы краудсорсинга, сборки), навигатор и публичная
витрина воркстримов.

Тест ставки: команды и партнёры любого вуза заходят и работают без согласований с чьим-либо
IT-отделом; вклад каждого виден сам собой в истории.

## Дорожная карта

Пункты идут по порядку: следующий начинается, когда слит предыдущий, — так в репозитории не
копятся ветки и Pull request'ы. Новые идеи по среде добавляются сюда, а не новой веткой.

**Сделано** — подробности в [хронике](#хроника)

1. **Карта воркстримов из папок** — [#42](https://github.com/SPBUEcon/econ-library/pull/42):
   паспорта `workstream.yml`, автосборка карты, таблица живости. Эта дорожная карта — его часть.
2. **Регистрация участников** — [#43](https://github.com/SPBUEcon/econ-library/pull/43): форма
   заявки на вход → строки в реестре через PR; автозапись выключена до согласования структуры
   реестра (переменная `REGISTRY_LIVE`).

**Дальше** — следующий по порядку пункт 3

3. **Единая сборка.** Один workflow после слияния в `main` запускает все скрипты сборки (главная и
   поиск, тезисы, задания, трек econ-3, карта) и коммитит результат. Сейчас сама собирается только
   карта: главная и поиск отстают, пока кто-то не запустит скрипты вручную.
4. **Чистый поиск.** Пустые заготовки `courses/` и `cases/` убраны (2026-10-21). Осталось решить
   с `projects/` (по [участникам и доступам](../../program/participants-and-access.md) § 7.2 — место
   для курсовых и ВКР, пока пустое) и корневым `meetings/` (правило для общих встреч, протоколов
   нет) и не включать в индекс README-заглушки в `data/`, `meetings/`, `deliverables/` (около 40
   одинаковых записей «Сырые данные», «Встречи воркстрима» и т. п.).
5. **Один вход.** `README.md` (текст) и главная (витрина). `DASHBOARD.md` и витрину воркстримов
   собирать скриптами из тех же источников или убрать: сейчас они ведутся руками и расходятся с картой.
6. **Правила работы с ветками** в [`CONTRIBUTING.md`](../../CONTRIBUTING.md): одна задача — одна
   ветка — один PR; не больше 2–3 открытых PR; PR без движения неделю — слить или закрыть; перед
   работой обновить `main`; не начинать PR поверх неслитого.
7. **Проверка реестра.** Скрипт ловит битые и повторные id, команду без капитана, внешнего
   участника без спонсора, `workstream_id` не из паспортов. Запускается на PR в `registry/` и
   внутри регистрации по заявке: PR бота через `GITHUB_TOKEN` проверки не запускают. Делать после
   согласования структуры реестра (открытый вопрос 3 в [`registry/README.md`](../../registry/README.md)).

**Открыто с первого хода**

- Сборка дайджеста из журнала стенда и форма краудсорсинга — инструменты из
  [механик вовлечения](../../stands/engagement.md).
- Прототип навигатора на `theses/catalog/units.csv` и журналах пилотных стендов
  ([архитектура](../../program/architecture.md) § 7). Поиск ([#39](https://github.com/SPBUEcon/econ-library/pull/39))
  уже индексирует `units.csv`; журналы стендов — нет.
- Определить шерпу и первых исполнителей (магистранты ИСвЭ как проводники по git).

## Как включиться

Инфраструктурный воркстрим — вход **через git / PR** (подробно — [гайд](../../guides/how-to-join.md)):

- **Через репозиторий** — возьмите задачу из Issues (метки среды: витрина, доска, шаблоны,
  автоматизация) и пришлите Pull request. Заявка на роль — по шаблону
  [«Заявка на вход»](https://github.com/SPBUEcon/econ-library/issues/new?template=join-workstream.yml), роль — по
  [ролям](../../roles/README.md). Первые исполнители — магистранты ИСвЭ как проводники по git.
- **Через контакт** — шерпа воркстрима (*уточнить*); технологический шерпа — ИИтех (veai).

Артефакт входа для нового участника — [соглашение о входе](../_template/onboarding.md). Витрина —
[`../../program/site/workstreams_board.html`](../../program/site/workstreams_board.html).
