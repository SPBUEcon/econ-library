## Что предлагается сделать

Из рабочей таблицы — в набор данных, из набора данных — в страницу с графиками на GitHub. Создайте
репозиторий `group-data`, подготовьте в нём файл данных (`attendance.csv` или `stakes.csv`), с помощью
ИИ сделайте страницу `index.html` с графиками ECharts, проверьте одно число руками, опишите выводы в
`README.md` и опубликуйте страницу. GitHub не работает или не пускает — возьмите GitVerse или
SourceCraft: [справка по альтернативам](../guides/repo-hosting-alternatives.md).

## Синопсис

Задание проводит студента по всему пути информационной системы в миниатюре: исходный документ →
очистка и приведение к форме → набор данных → хранилище с историей (GitHub) → представление
(дашборд) → проверка числа по источнику → изменение требований на ходу. ИИ пишет код, студент
отвечает за данные, запрос, публикацию и правильность числа.

Вариант А добавляет работу с персональными данными: список группы и посещаемость студенты собирают
сами, а обезличивание — часть задания. Вариант Б — первый шаг к бирже прогнозов: студент оценивает
не «сбудется ли ставка», а «можно ли будет её проверить в срок».

Задание рассчитано на быстрый вход: 20 минут по умолчанию, остальное — в пределах занятия. Важнее
довести дело до опубликованной страницы, чем пройти все шаги. Всё, что нужно, есть в этой карточке:
преподаватель только объявляет задание и время. Стратегически задание — первая версия **дашборда
группы**: страница, где сначала отслеживается посещаемость, а потом другие задачи и задания группы.

## Работа в группе

Задание можно и лучше делать группой. Тогда частью результата становится то, как вы организовались:

1. **Состав.** Соберите группу за первые минуты, без подсказки преподавателя.
2. **Роли.** Распределите их, например: данные (подготовка и обезличивание CSV), запрос к ИИ и
   страница, проверка чисел, публикация и README. Один человек может держать две роли.
3. **Задачи.** Шаги 2 и 3 можно вести параллельно: страницу делают по 3–4 строкам будущего CSV.
4. **Один репозиторий** на группу: владелец добавляет остальных как соавторов
   (**Settings → Collaborators → Add people**). В README впишите состав и роли (ники, без ФИО).

## Логика выполнения

### Шаг 1. Создайте репозиторий · ≈ 2 мин

На GitHub: **New repository** → имя `group-data` → **Public** → галочка **Add a README file** →
**Create repository**. Не получается зарегистрироваться или GitHub не открывается — создайте
публичный репозиторий на GitVerse или SourceCraft: [справка по альтернативам](../guides/repo-hosting-alternatives.md).

> **Правило репозитория:** в него попадает только то, что можно показать всем. Файл с фамилиями не
> загружайте даже на минуту: удалённый файл остаётся в истории коммитов и виден любому.

### Шаг 2А. Соберите и обезличьте посещаемость · ≈ 8 мин

**Откуда взять данные — решаете сами.** Список группы и отметки о посещении: ваши записи, староста,
чат группы, перекличка на сегодняшнем занятии. Если данных за прошлые занятия нет, начните с
сегодняшнего: одна дата — тоже набор данных, его можно пополнять. В README напишите, откуда взяли.

> **Где работать.** Только на своём компьютере, в Excel или LibreOffice Calc. Не загружайте список с
> фамилиями в Google Таблицы, ИИ-чаты и другие онлайн-сервисы: это персональные данные ваших
> однокурсников. ИИ-помощнику позже покажете только обезличенный файл.

1. Сохраните собранный список в отдельную папку на компьютере, не в папку репозитория: `raw_attendance.xlsx`.
2. Приведите таблицу к форме «одна строка — один студент, один столбец — одно занятие». Заголовки
   занятий — даты в формате ГГГГ-ММ-ДД (`2026-10-08`). В ячейках `1` — был, `0` — не был, пусто —
   студента ещё не было в списке. Замену «+» → 1 и «н» → 0 делайте через **Ctrl+H**.
3. Удалите всё, что указывает на человека, кроме столбца ФИО: номер зачётки, почту, телефон, пометки
   вроде «староста» или «болел».
4. **Перемешайте строки.** Добавьте столбец, в каждую его ячейку впишите `=СЛЧИС()` (в английском
   Excel `=RAND()`), выделите таблицу и отсортируйте по этому столбцу. Зачем: если раздать коды по
   алфавиту, любой со списком группы восстановит фамилии.
5. Добавьте столбец `code` и заполните его кодами `S01`, `S02`, `S03`… по порядку уже после
   перемешивания. Формула для строки 2: `="S"&ТЕКСТ(СТРОКА()-1;"00")`, затем протянуть вниз. Буква S
   в коде — латинская.
6. Скопируйте столбцы ФИО и `code` на отдельный лист «ключ» в `raw_attendance.xlsx`. Ключ остаётся
   только у вас; для графиков он не нужен, его можно и удалить.
7. В рабочей таблице удалите столбцы ФИО и СЛЧИС. Первым столбцом должен стать `code`.
8. **Файл → Сохранить как → CSV UTF-8 (разделитель — запятая)**, имя `attendance.csv`. В LibreOffice:
   «Текст CSV», кодировка «Юникод (UTF-8)», разделитель — запятая.
9. Откройте `attendance.csv` в Блокноте и проверьте глазами: нет ни одной фамилии, первая строка
   начинается со слова `code`, значения разделены запятыми.
10. Загрузите в репозиторий только этот файл: **Add file → Upload files → attendance.csv → Commit changes**.

| Было (на компьютере) | Стало (в репозитории) |
|---|---|
| `ФИО │ 08.10 │ 15.10` | `code,2026-10-08,2026-10-15` |
| `Иванов И. │ + │ н` | `S07,1,1` |
| `Петрова А. │ + │ +` | `S12,1,0` |

> Обезличенные данные — не то же самое, что анонимные. В маленькой группе человека узнают по
> сочетанию признаков: «единственный, кто не был ни разу». Поэтому в README и на показе обсуждайте
> занятия и группу в целом, а не отдельные коды.

### Шаг 2Б. Соберите ставки однокурсников · ≈ 8 мин

1. Найдите портфолио однокурсников сами: спросите ссылки в чате группы или у соседей, поищите на
   GitHub по имени репозитория `econ-portfolio`. Берите только открытые репозитории.
2. В папке `works/` найдите работу по Заданию 1, в ней раздел «Ставка на год» в `report.docx` или в
   слайдах. Если в паспорте `report.md` заполнены поля `stake`, `stake_deadline`, `stake_confidence`,
   можно взять их оттуда.
3. Внесите **не меньше 8 ставок** (за 20 минут — сколько успеете, остальные — в пределах занятия) в таблицу Excel с колонками из таблицы ниже. Названия колонок
   пишите латиницей, как в таблице.
4. Заполните колонку `check`, ответив на три вопроса: (1) есть ли в ставке число или однозначный
   признак; (2) есть ли дата и успеет ли к ней выйти источник (квартал кончается раньше, чем выходит
   отчёт о нём); (3) понятно ли, где проверить. Три «да» → `да`, одно «нет» → `частично`, два и
   больше → `нет`. В `comment` — одна фраза почему.
5. **Сохранить как → CSV UTF-8 (разделитель — запятая)**, имя `stakes.csv`. Текст с запятыми Excel
   сам возьмёт в кавычки. Загрузите файл в репозиторий.

| Колонка | Что вписать | Пример |
|---|---|---|
| `author` | Ник GitHub автора ставки | ivanova-a |
| `topic` | Компания или технология | Ozon |
| `stake` | Текст ставки, коротко | Закон о единой цене опубликован |
| `deadline` | Срок проверки, ГГГГ-ММ-ДД | 2027-10-01 |
| `confidence` | Уверенность автора, число 0–100 | 55 |
| `where_to_check` | Где проверять | Портал правовой информации |
| `check` | да / частично / нет | да |
| `comment` | Почему так оценили | Признак однозначный, источник есть |

> Вы оцениваете не автора и не то, сбудется ли ставка, а то, можно ли будет её проверить в срок.
> Оценки вида «слабая работа» в таблицу не пишите.

### Шаг 4. Требование заказчика · в пределах занятия

Заказчик меняет требования на ходу. Если преподаватель назвал своё требование — выполняйте его. Если
нет — возьмите одно из списка своего варианта. Допишите запрос к ИИ так, чтобы выполнить требование,
не начиная с нуля, и обновите `index.html`.

**Вариант А**

1. Число студентов, у которых три и больше пропусков подряд, — числом, без кодов на экране.
2. Тепловая карта: строки — коды, столбцы — занятия. Подумайте: можно ли такую страницу держать открытой?
3. Крупно — дата занятия с наименьшей явкой и разница со средним в процентных пунктах.
4. Всё на одном экране телефона, без горизонтальной прокрутки.

**Вариант Б**

1. Вертикальная линия «сегодня» и подсветка ставок со сроком в ближайшие 3 месяца.
2. Колонка `ai_confidence` — уверенность ИИ по каждой ставке — рядом с уверенностью автора.
3. Страница сама отмечает строки: нет срока, нет источника, в ставке нет числа.
4. Всё на одном экране телефона, без горизонтальной прокрутки.

## Если что-то пошло не так

| Что случилось | Что делать |
|---|---|
| Не получается зарегистрироваться на GitHub, не открывается сайт | Возьмите GitVerse или SourceCraft: [справка по альтернативам](../guides/repo-hosting-alternatives.md) |
| Загрузили файл с фамилиями | Удалите репозиторий целиком: **Settings → Danger Zone → Delete this repository**. Создайте заново и сообщите преподавателю. Удаление одного файла не убирает его из истории |
| В CSV «кракозябры» вместо букв | Файл сохранён не в UTF-8. Пересохраните: «CSV UTF-8 (разделитель — запятая)» |
| Excel поставил точку с запятой | Пересохраните в формате CSV UTF-8 или попросите ИИ поддержать оба разделителя |
| ИИ прислал код с пропусками или оборвал ответ | Напишите: «Пришли файл целиком, без сокращений». Если не помогает — попросите прислать файл двумя частями или смените помощника (для кода надёжнее DeepSeek и Qwen) |
| Страница пустая | Нажмите **F12** → вкладка **Console**, скопируйте красную ошибку и отдайте ИИ вместе с кодом |
| ECharts не загрузился | Нет доступа к `cdn.jsdelivr.net`. По Wi-Fi скачайте `echarts.min.js` с этого адреса, загрузите в репозиторий, в теге `script` замените адрес на `echarts.min.js` |
| Pages показывает 404 | Подождите 2 минуты; главный файл должен называться `index.html` и лежать в корне репозитория |
| Страница не открывается | С мобильного интернета адреса `github.io` и другие бывают недоступны. Проверьте по Wi-Fi аудитории; репозиторий засчитывается и без страницы |
| Нет данных за прошлые занятия или открытых портфолио | А: начните с сегодняшней переклички. Б: возьмите другой вариант |
