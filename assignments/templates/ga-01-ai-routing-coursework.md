## Что предлагается сделать

Спроектируйте маршрутизатор, который распределяет задачи клиентских сервисов геоплатформы между
ИИ-моделями разной стоимости с учётом чувствительности данных. Реализуйте его прототип для сценариев
1–3, сравните стратегии маршрутизации на эталонном наборе по качеству, стоимости и времени и
постройте экономическую модель, обосновывающую выбор стратегии для партнёра.

## Синопсис

Партнёр рассматривает ИИ в трёх клиентских сценариях возрастающей сложности: **справочный чат**
(инструкции, тарифы, логика сервисов), **чат-консультант** (как решить задачу клиента средствами
сервиса — выбрать точку, построить зону, сделать выводы) и **геоотчёт по запросу** (свободный запрос →
расчёт на платформе → выводы). Использовать самую сильную модель для всех задач экономически
неоправданно, самую дешёвую — теряется качество; к тому же часть данных нельзя выпускать за пределы
контура.

**Суперзадача партнёра:** определить, сколько стоят ответ, консультация и геоотчёт, подготовленные с
ИИ, и предложить способ снизить эту стоимость без потери качества и без нарушения требований к данным.

## Логика задачи

Задание соединяет слой Ф (архитектура и работающий прототип) и слой И (эксперимент и экономическая
модель): ни одна из частей не имеет смысла без другой. Ловушка — сравнивать модели «на глаз»; защита —
эталонный набор с машинной проверкой и журнал стоимости каждого шага. Вторая ловушка — считать только
токены; защита — стоимость ошибок, дошедших до клиента, и передач сотруднику. Набор, методики и
шаблоны переходят следующей команде (наследование) и стенду [ГИС · спорт СПб](../../stands/geo-sport-spb/README.md)
(переопыление).

## Содержание

### Архитектура

Компоненты маршрутизатора:

- **база знаний и поиск** — ответ только по найденным фрагментам, со ссылкой на источник;
- **кэш похожих вопросов** — проверенный ответ без обращения к модели;
- **классификатор намерения и сложности** — тип обращения (продукт, покупка, жалоба, техническая
  проблема, консультация, запрос отчёта) и наличие готовой методики или шаблона;
- **политики маршрутизации** в строгом порядке: допустимость передачи данных за пределы контура
  (персональные данные, коммерческая тайна клиента, лицензии) → сложность задачи → бюджет и режим;
- **каскад эскалации** — не прошла машинная проверка → ярус выше с описанием ошибки; ответ невозможен →
  сотрудник партнёра;
- **журнал стоимости и качества** — модель, объём токенов, стоимость, время, результат проверки.

Базовые ярусы (допускается уточнять):

| Ярус | Типовые задачи в сценариях 1–3 | Средство |
|---|---|---|
| Без модели | Ответ из кэша, поиск по базе знаний, расчёт на платформе, проверка чисел в отчёте | Поисковый индекс, PostGIS, API сервисов |
| Малые модели | Намерение, разбор запроса в параметры, выбор методики или шаблона | Локальные модели небольшого размера |
| Средние модели | Ответ по найденным фрагментам, ведение по методике, текст выводов | Крупные локальные или облачные модели |
| Тяжёлые модели | Нестандартные консультации и запросы вне шаблонов | Наиболее сильные доступные модели |

Результат раздела: архитектурная схема; политики и критерии эскалации; не менее пяти записей
архитектурных решений (решение, рассмотренные альтернативы, обоснование).

### Прототип и эксперимент

**Эталонный набор:** не менее 45 задач для пары (по 15 на сценарий) или 30 для одного исполнителя (по
15 на два сценария). Для каждой задачи — формулировка, эталон, способ автоматической проверки,
сложность, признак чувствительности данных.

| Сценарий | Пример формулировки | Эталон | Проверка |
|---|---|---|---|
| 1. Справочный чат | «Как выгрузить слой в формате GeoJSON?» | Шаги из инструкции и ссылка на раздел | Ключевые факты и совпадение ссылки |
| 1. Справочный чат | «Сколько стоит тариф для команды из пяти человек?» | Значение из прайса или передача менеджеру | Точное совпадение или факт передачи |
| 2. Консультант | «Как выбрать место для кофейни в Приморском районе?» | Шаги по методике: слои, зона, интерпретация | Сверка шагов с методикой; экспертная выборка |
| 2. Консультант | «Сколько конкурентов в зоне пешей доступности моего магазина?» | Геокодирование → изохрона → выборка по категории → подсчёт | Сверка шагов с методикой |
| 3. Геоотчёт | «Оцени район вокруг Невского, 100, для кофейни» | Параметры, шаблон, контрольные числа | Сравнение параметров; числа в тексте = расчёт |
| 3. Геоотчёт | «Сколько жилых домов дальше 500 м от ближайшей школы?» | Эталонный SQL и число на тестовой базе | Запрос выполняется; число совпадает |

Итоговые формулировки согласуются с куратором партнёра.

**Прототип:** Python, не менее трёх ярусов (без модели, малая, сильная). Для сценария 3 достаточно
цепочки «запрос → параметры → расчёт через API или тестовую базу → текст выводов → проверка чисел».
Каждое обращение — в журнал.

**Эксперимент:** четыре стратегии — всё сильной моделью; всё дешёвой; статическое назначение по типам;
каскад с эскалацией. По каждой стратегии и сценарию: доля верных ответов, средняя стоимость и время,
доля эскалаций и передач сотруднику. Сводная таблица и график «стоимость — качество» с границей
эффективных стратегий; отдельно — где каскад не даёт выигрыша и эффект кэша для сценария 1. Версии
моделей, параметры и скрипт запуска фиксируются в репозитории.

### Экономическая модель

Стоимость задачи с учётом ошибок, дошедших до клиента:

```
C_задачи = Σ d_i · c_i + C_эскалаций + C_передач + p_ошибки · C_исправления
```

где `d_i` — доля задач на ярусе `i`, `c_i` — стоимость задачи на ярусе, `C_эскалаций` — повторные
попытки, `C_передач` — время сотрудника, `p_ошибки` — вероятность ошибки у клиента, `C_исправления` —
стоимость исправления с учётом потери доверия.

Блоки: стоимость ответа, консультации и отчёта при заданном месячном потоке; сравнение со стоимостью
работы сотрудника первой линии и эксперта; себестоимость геоотчёта; облако или собственный GPU-сервер
(точка безубыточности, совокупная стоимость владения); цена требований к данным (только локальные
модели — в деньгах и качестве); кривая удешевления по мере роста кэша, методик и шаблонов; анализ
чувствительности. Excel: листы допущений, расчётов и сценариев; у каждого допущения — источник.

### Расширенная часть (по выбору, для пары)

Прототип сценария 3 на тестовом контуре партнёра с тремя и более шаблонами отчётов **или** проектный
раздел о переносе архитектуры на более сложные сценарии: что переиспользуется, что добавляется, как
меняется структура затрат.

## Логика выполнения

| Шаг | Недели | Что делать | Контрольная точка · где фиксировать |
|---|---|---|---|
| 1. Погружение и постановка | 1–3 | Сервисы и обращения; каталог задач по сценариям с разметкой сложности и чувствительности | Каталог задач и первая версия набора · куратор партнёра |
| 2. Архитектура | 4–7 | Схема, политики, выбор моделей, критерии эскалации и передачи | Архитектурный документ, обсуждение с партнёром |
| 3. Прототип и эксперимент | 8–12 | Маршрутизатор, поиск, проверки; прогон стратегий | Работающий прототип и таблица результатов |
| 4. Экономика и защита | 13–16 | Модель, сценарии, рекомендации | Записка, репозиторий, модель, защита · куратор партнёра |

В паре экономическая модель начинается со второго этапа. **Пара:** первый — архитектура и прототип,
второй — эталонный набор, план эксперимента и экономическая модель; эксперимент и выводы — совместно.
**Один исполнитель:** два сценария (рекомендуются 1 и 3), набор ≥ 30 задач, три стратегии (без
статического назначения), один сценарий потока и одно сравнение вариантов размещения.

## Ориентировочный результат

Пояснительная записка 25–35 страниц (пара — 35–45); репозиторий с прототипом и инструкцией запуска
эксперимента; эталонный набор в машиночитаемом формате; экономическая модель (XLSX); презентация
10–12 слайдов; записка партнёру 1–2 страницы. Курсовая сдаётся по вузовскому порядку; в этот
репозиторий — только открытая часть (синтетический набор, код без ключей, обезличенные результаты).

## Критерии приёмки

| Раздел | Вес | Что оценивается |
|---|---|---|
| Архитектура | 25% | Полнота компонентов; обоснованность политик, эскалации и передачи сотруднику; записи архитектурных решений |
| Прототип и эксперимент | 30% | Работоспособность, качество набора, корректность и воспроизводимость, анализ по сценариям |
| Экономическая модель | 25% | Прозрачность допущений, учёт ошибок и передач, сравнение с сотрудниками, сценарии и чувствительность |
| Записка и защита | 20% | Логика, качество рекомендаций партнёру, ответы на вопросы |

Дополнительно: честный разбор случаев, где стратегия не дала выигрыша; расширенная часть.

## Входные требования и компетенции

На входе: Python, базовый SQL, основы экономики фирмы. Осваивается по ходу: поиск с генерацией (RAG),
API языковых моделей, PostGIS на уровне запросов, оценка моделей на эталонном наборе, совокупная
стоимость владения, анализ чувствительности.

## Ресурсы и данные

**Ресурсы партнёра — в согласовании:** база знаний сервисов, обезличенные обращения, описание типовых
задач и методик, тестовый контур, доступ к моделям с лимитом бюджета, участие куратора в контрольных
точках 1, 2 и 4. Пока ресурсов нет — работа начинается на публичных материалах платформы и открытых
данных OpenStreetMap.

**Условия работы с данными:** данные партнёра — только по соглашению о конфиденциальности; обращения —
только в обезличенном виде, маскирование персональных данных до передачи во внешние модели; данные
партнёра и лицензированные наборы не публикуются и не передаются во внешние модели без разрешения; в
открытой части репозитория — только открытые или синтетические данные; ключи доступа в репозиторий не
кладутся. Правила — [`data-collection`](../../rules/data-collection.md),
[`ai-usage`](../../rules/ai-usage.md).
