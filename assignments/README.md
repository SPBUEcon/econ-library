# 📝 Задания: архив, выдача, накопительные досье

Здесь лежит **источник заданий** Мастерской для групп и потоков, то есть архив, из которого
преподаватель выдаёт задания, а студенты их выполняют. Архив сквозной: он не привязан к одному
семестру и одной дисциплине, задания из него выдаются в разные [треки](../tracks/README.md) и годами
переиспользуются.

> Проект модели заведён 2026-09-30 (рабочая версия, подлежит обсуждению). Каталог заданий — черновик:
> поля и перечни открытые, дополняются через Pull request.

> **Витрина архива** — [`site/index.html`](site/index.html) (публично:
> https://spbuecon.github.io/econ-library/assignments/site/index.html): все задания с фильтрами по роду,
> типу, навыку, масштабу и досье. Собирается из CSV: `python assignments/site/build.py`.

## Зачем отдельный слой

Задание в мастерской — не «контрольная к занятию», а **короткий горизонт** (governance § 1): за срок
получить осязаемый результат, командный или индивидуальный. Хорошее задание работает на три стороны:

1. **Студенту** даёт результат в одной из форм и тренирует конкретный навык.
2. **Курсу** обновляет кейсы лекций: компании меняются, а разбор, сделанный студентом в этом семестре,
   становится материалом для следующего занятия.
3. **Воркстриму** поставляет «кирпичи» (данные, модели, оценки) через переопыление.

Отсюда главное решение: у заданий есть не только **текст**, но и **накопитель**. Это досье, куда
оседают результаты и откуда формируется следующее задание.

## Модель: четыре сущности

```
тип · навык · механика           (справочники: из чего собирается задание)
        │
        ▼
ШАБЛОН (архив)  ──выдача──►  ВЫДАЧА (экземпляр)  ──сдача──►  РЕЗУЛЬТАТ
  конкретное                   кому, когда, с какими          PR в репозиторий
  параметрическое              параметрами и по какой          │
  эстафетное ◄──────────┐      версии досье                    ▼
                        │                                  ДОСЬЕ (накопитель)
                        └─── состояние досье корректирует ── модель · хроника · источники
                             следующую выдачу                  · пробелы · ставки
```

| Сущность | Что это | Где |
|---|---|---|
| **Шаблон** | Задание в архиве: формулировка, тип, проверяемые навыки, механика, критерии приёмки | [`catalog/templates.csv`](catalog/templates.csv), карточки — [`templates/`](templates/) (пример — [`rb-02`](templates/rb-02-red-bull-business-model.md), шаблон — [`_card-template.md`](templates/_card-template.md)) |
| **Выдача** | Конкретный экземпляр: шаблон × трек × кому × параметры × версия досье × сроки | [`catalog/issues.csv`](catalog/issues.csv) |
| **Результат** | Сданная работа — PR в досье или в папку трека/воркстрима | по ссылке из выдачи |
| **Досье** | Накопительный объект (компания, отрасль, технология, событие), над которым работают сменяющие друг друга участники | [`dossiers/`](dossiers/README.md) |

## Три рода заданий (источник текста)

| Род | `kind` | Как получается формулировка | Когда хорош | Пример |
|---|---|---|---|---|
| **Конкретное** | `fixed` | Один текст, выдаётся многим как есть | Базовые упражнения, сравнимые результаты, семинарская работа | «Разберите Red Bull Stratos как хлопушку» (`tpl07`) |
| **Параметрическое** | `param` | Шаблон + параметры из пула → индивидуальный вариант | Потоки, где нужно много непересекающихся вариантов | «Разберите компанию `{company}` по трём укладам» с пулом `business-models.csv` (`tpl01`) |
| **Эстафетное** | `relay` | Шаблон + **состояние досье** → задание на следующий шаг | Живые кейсы, которые обновляются из семестра в семестр | Досье Red Bull: базовая модель → актуализация → оппонирование → ставка (`rb-*`) |

Род не ограничивает тип: параметрическим может быть и доклад, и задача, и прототип.

## Справочники

### Типы заданий (что сдаётся) — [`catalog/types.csv`](catalog/types.csv)

Типы соответствуют формам результата короткого горизонта из governance (§ 1): отчёт · приложение ·
исследование · модель · данные · ИС · активность · событие · проект · стартап. Ядро:

- аналитический доклад и разбор кейса;
- исследование (поиск и сбор данных с источниками);
- разработка приложения, сервиса или прототипа;
- решение задачи (с проверяемым ответом или обоснованием);
- модель (экономическая, организационная, финансовая);
- набор данных;
- ставка, то есть прогноз с датой проверки;
- событие (дебаты, круглый стол, интервью с практиком);
- рецензия и оппонирование.

### Проверяемые навыки — [`catalog/skills.csv`](catalog/skills.csv)

Задание проверяет не «знание темы», а **навык**, и навык должен быть виден в цифровом следе:

| Навык | Что видно в результате |
|---|---|
| Поиск и верификация информации | Источники первого уровня, даты обращения, расхождения источников названы |
| Анализ и структурирование | Разметка по рамке без пропусков, выводы следуют из данных |
| Сборка модели | Связная модель: элементы, связи, «что сломается первым» |
| Ставка и суждение | Проверяемый прогноз: что, к какой дате, по какому признаку, с какой уверенностью |
| Работа с данными | Таблица по правилам `rules/data-collection.md`, воспроизводимая обработка |
| Разработка | Работающий прототип, который можно запустить |
| Организация | Собранное событие или команда: люди пришли, результат зафиксирован |
| Коммуникация | Доклад, презентация, текст для внешнего читателя |
| Оппонирование | Найдены слабые места чужой модели, предложены проверки |
| Работа с ИИ | Где и как использован ИИ, что проверено по первоисточнику |
| Наследование | Принят пакет предшественника, передан пакет дальше |
| Работа в поле | Интервью, наблюдение, контакт с партнёром |
| Архитектура ИС и интеграции | Схема компонентов и потоков данных, интерфейсы, точка встраивания |
| Моделирование процессов | Процесс AS-IS/TO-BE в нотации, точка автоматизации или встраивания ИИ |

Последние два навыка — **фундамент ИС** (слой Ф): курс их не преподаёт, они приходят из базовых курсов, но
на стендах проверяются ([архитектура v2](../program/architecture.md) § 4, [стенды](../stands/README.md)).

Одно задание проверяет 1–3 навыка. Больше — и оценка размывается.

### Механики — [`catalog/mechanics.csv`](catalog/mechanics.csv)

Механика — способ, которым задание выдаётся, связывается с другими и проверяется. Ключевые:

| Механика | Суть |
|---|---|
| **Параметрическая генерация** | Шаблон × пул из каталога дисциплины (компании, отрасли, технологии). Технология × отрасль даёт 10 × 15 = 150 уникальных вариантов |
| **Выбор из пула с бронью** | Студент сам берёт вариант, занятый вариант помечается в `issues.csv`. Внутри группы варианты не повторяются |
| **Эстафета по досье** | Следующий участник принимает досье и делает следующий шаг. Задание зависит от стадии досье |
| **Актуализация (дельта)** | «Что изменилось с версии vN»: новые события, устаревшие цифры, сломанные выводы |
| **Оппонирование** | Следующий участник атакует модель предшественника. Выживший вывод повышает зрелость досье |
| **Ставка с отложенной проверкой** | Прогноз с датой разрешения. Ставку разрешает уже другой участник в другом семестре, так видна калибровка |
| **Доска пробелов** | Открытые вопросы досье становятся микро-заданиями (баунти) на одно-два занятия |
| **Переопыление** | Модель, собранная на одном объекте, переносится на другой (Red Bull → партнёр воркстрима) |
| **Зеркало ИИ** | Студент получает ИИ-разбор и ищет в нём ошибки по первоисточникам |
| **Одна тема — разные навыки** | Над одним досье одновременно работают аналитик, разработчик, организатор, «ставочник» |
| **Сборка события** | Результат — проведённое событие (дебаты, интервью, воркшоп), а не текст о нём |

## Как задание корректируется накопленным

Для эстафетных заданий формулировка **вычисляется из состояния досье**, а не пишется заново каждый
семестр. Перед выдачей преподаватель (или ИИ-ассистент, с проверкой преподавателем) читает досье и
применяет правила:

| Состояние досье | Что выдаётся |
|---|---|
| Стадия «зерно»: есть только строки каталога, цифры со слайдов не проверены | Верификация и каркас: проверить цифры, собрать хронику с источниками |
| Стадия «каркас», модели нет | Базовая модель по трём укладам |
| Модель есть, последнее обновление старше семестра | Актуализация: дельта с прошлой версии |
| Модель есть, оппонирования не было | Оппонирование |
| В `open-questions.md` есть пробелы с приоритетом | Микро-задания с доски пробелов |
| У ставки прошла дата разрешения | Разрешить ставку: сбылось, не сбылось, почему |
| Модель выдержала оппонирование | Переопыление на другой объект; обновление кейса в каталоге дисциплины |
| Досье не обновлялось два семестра | Помечается «устарело»; первое задание — актуализация |

Стадии зрелости досье описаны в [`dossiers/README.md`](dossiers/README.md). В выдаче фиксируется
**версия досье на момент выдачи**. Так видно, от какого состояния отталкивался участник, и работу можно
честно оценить даже после того, как досье ушло дальше.

## Выдача: как получается индивидуальный вариант

1. **Выбрать шаблон** в `templates.csv` по дисциплине, блоку, навыку, треку.
2. **Разрешить параметры** одним из способов:
   - **вручную**: преподаватель назначает;
   - **бронь**: студент выбирает из пула, вариант блокируется для группы;
   - **детерминированно**: индекс в пуле = хэш(ник + `template_id` + `semester_id`) mod размер пула.
     Вариант воспроизводим и не зависит от того, кто выдаёт;
   - **ИИ-формулировка**: для эстафетных заданий ИИ собирает текст из шаблона и состояния досье;
     преподаватель проверяет до выдачи ([`../rules/ai-usage.md`](../rules/ai-usage.md)).
3. **Записать выдачу** строкой в `issues.csv`: шаблон, трек, группа, исполнитель (ник или `team_id`),
   параметры, версия досье, даты. В колонке «Задание» в `tracks/<трек>/<семестр>/sessions.md` —
   ссылка на `issue_id`.
4. **Сдача** — Pull request (правило [`../rules/team-work.md`](../rules/team-work.md)): в досье, если
   задание эстафетное, иначе в папку трека или воркстрима.
5. **Приёмка** — по критериям шаблона и проверяемым навыкам. Принятый результат обновляет досье
   (версия +1, запись в `changelog.md`).

## Приватность и оценки

- Репозиторий публичный: в выдачах и досье — **только ники или `team_id`**, без ФИО.
- **Оценки сюда не пишутся.** Здесь фиксируются только факты: выдано, сдано, принято, на доработке.
  Оценка — в вузовской ведомости (академический контур).
- Данные — только открытые, с источником и датой обращения
  ([`../rules/data-collection.md`](../rules/data-collection.md),
  [`../rules/sources-and-citation.md`](../rules/sources-and-citation.md)).

## Открытые вопросы

- Сколько навыков в одном задании засчитывается в оценку и как сводится траектория участника.
  Это решение класса C4 (оценивание).
- Нужен ли агент `assignment-issuer` (выдача по состоянию досье) и скрипт детерминированной
  генерации вариантов. Агенты добавляются через PR ([`../rules/ai-usage.md`](../rules/ai-usage.md)).
- Кто держит досье между семестрами: преподаватель, владелец профильного воркстрима или
  студент-куратор досье.
