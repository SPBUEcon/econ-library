# Накопительные досье

**Досье** — живой объект, над которым работают сменяющие друг друга участники: компания, отрасль,
технология, событие. Досье — **цифровой след как субстрат сборки** (governance § 3): каждый принятый
результат оседает здесь, и из состояния досье вычисляется следующее задание.

Досье отличается от кейса в каталоге дисциплины. Строка каталога (`bm01` Red Bull) — сжатая версия для
лекции. Досье — полная рабочая версия с хроникой, источниками, пробелами и ставками. Когда досье
дозревает, оно обновляет строку каталога. Так кейс лекции следует за реальной компанией.

```
каталог дисциплины (bm01) ──зерно──► ДОСЬЕ ──задания по стадии──► участники
        ▲                               │  ▲                           │
        └────── стадия «кейс» ──────────┘  └──── принятые PR ◄─────────┘
```

## Состав досье

| Файл | Что | Кто пишет |
|---|---|---|
| `README.md` | Паспорт: объект, стадия, версия, маршрут заданий, кто вносил (ники) | Куратор досье |
| `model.md` | Текущая модель объекта в рамке дисциплины | Участники через PR |
| `timeline.csv` | Хроника событий: дата, событие, уклад, механика, источник, дата обращения, кто добавил | Участники |
| `sources.csv` | Источники досье | Участники |
| `open-questions.md` | Пробелы и спорные места с приоритетом — доска пробелов | Все; закрываются заданиями |
| `changelog.md` | Версии: что изменилось в модели, по какой выдаче | Куратор при приёмке |
| `contributions/` | Сданные работы: `<семестр>-<ник>-<template_id>.md` | Участники |

## Стадии зрелости

| Стадия | Признак | Выход на следующую стадию |
|---|---|---|
| **Зерно** | Только строки каталога дисциплины; цифры со слайдов не проверены | Цифры проверены, хроника ≥ 10 событий с источниками |
| **Каркас** | Проверенные факты и хроника; модели нет | Модель по рамке, все ячейки заполнены или помечены пробелом |
| **Модель** | Модель собрана | Модель выдержала оппонирование: ≥ 1 рецензия, уязвимости закрыты или признаны |
| **Кейс** | Модель проверена; есть ставки | Досье обновляет строку каталога и материалы лекции; работа продолжается актуализацией и переопылением |
| **Устарело** | Досье не обновлялось 2 семестра | Актуализация возвращает на прежнюю стадию |

Стадия и версия указываются в паспорте досье и записываются в каждую выдачу (`red-bull@v0`).

## Правила

- **Сдача только через PR** в папку досье. Куратор досье проверяет и поднимает версию.
- **Не переписывать чужое молча.** Правка модели фиксируется в `changelog.md`: что поменялось и почему.
  Опровергнутое не удаляется, а помечается со ссылкой на опровержение.
- **Честное «не нашёл» — тоже вклад.** Закрытый пробел с пометкой «не найдено, искали здесь» экономит
  время следующему.
- Данные открытые, у каждой цифры источник и дата обращения. Персональных данных нет: исполнители —
  по никам.

## Новое досье

1. Создать папку `dossiers/<объект-латиницей>/` с файлами из таблицы «Состав досье».
2. В паспорте указать объект, куратора, стадию «зерно», v0 и строки каталога-источника.
3. Перенести в `model.md` то, что есть в каталоге, с пометкой «v0 — из каталога, не проверено».
4. Добавить задания `<объект>-NN` в [`../catalog/templates.csv`](../catalog/templates.csv) с
   `parent_template` и `entry_stage`, строку в таблицу выше.
